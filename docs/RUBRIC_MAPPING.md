# UBO Project Rubric Mapping

This document maps repository evidence to the functional-prototype evaluation criteria. It is a checklist, not a claim that an item is complete until the corresponding real evidence exists.

| Evaluation area | Repository evidence | Final evidence still required |
|---|---|---|
| Problem and scope | `README.md`, problem statement, intended users, human decision boundary | Confirm final scope used in the demo |
| Data and traceability | `docs/DATA_CARD.md`, official source/license, reproducible preprocessing scripts | Record the exact categories, splits, counts, and transformations actually used |
| Technique/model and decision | Deep patch detector, histogram baseline, model card | Run both methods and preserve real comparison outputs |
| Architecture and integration | `app.py`, `docs/ARCHITECTURE.md` | Demonstrate image → model → evidence → operator workflow live |
| Validation and results | `scripts/calibrate_threshold.py`, `scripts/evaluate.py`, `docs/VALIDATION_PLAN.md` | Produce real JSON/CSV metrics, error cases, and edge-case analysis |
| Reproducibility and demonstration | `requirements.txt`, README commands, tests, CI workflow | Re-run setup on a clean environment and record demo hardware |
| Responsibility, security, AI | `docs/ETHICS_SECURITY_RISKS.md`, `docs/AI_USE_DECLARATION.md` | Keep the AI declaration current and verify no secrets/personal data are committed |

## Definition of done before EVAL-01

- The application starts from the documented command.
- At least one category has a generated memory bank and frozen validation threshold.
- The live demo accepts an image and produces an observable result and heatmap.
- Baseline and selected model have been compared using real outputs.
- Final test metrics are generated by script, not manually entered.
- False positives and false negatives have been inspected and discussed.
- The architecture diagram matches the code that is actually demonstrated.
- Another team member can install and run the prototype using the README.
- All three team members can explain data, model, threshold, architecture, errors, risks, and limitations.
- The generative-AI declaration reflects the actual material use of AI tools.
